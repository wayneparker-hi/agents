# 领域建模完整工作流

这个工作流将限界上下文转化为详细的领域模型，包括聚合、实体、值对象和领域事件的设计。

## 目标

- 从业务需求创建完整的领域模型
- 设计聚合和一致性边界
- 实现业务规则和不变量
- 产出可实现的模型和代码框架

## 工作流阶段

### Phase 1-3: 事件风暴与需求分析
（详见 event-storming skill）

使用事件风暴识别：
- 领域事件（已发生的事）
- 命令（触发事件的动作）
- 用户和角色
- 业务规则和策略

**输出**：事件流图、命令清单、规则列表

### Phase 4: 命令识别
**时长**：1 小时

从事件反推命令：
1. 每个事件由什么命令触发？
2. 命令的输入和输出是什么？
3. 命令的前置条件是什么？
4. 命令如何改变系统状态？

**输出**：命令清单和规范

### Phase 5: 聚合识别
**时长**：2 小时

从命令识别聚合：
1. 每个命令操作什么对象？
2. 哪些对象必须一起变化？
3. 哪些业务不变量需要保护？
4. 聚合的边界在哪里？

**使用 Agent**：domain-modeler
```
Prompt: 从这些命令和业务规则设计聚合。
提供：
- 聚合根和内部实体
- 一致性规则
- 聚合边界说明
```

**输出**：聚合清单、聚合设计文档

### Phase 6: 聚合详细设计
**时长**：3 小时

为每个聚合：
1. 定义根实体及其标识
2. 定义内部实体和值对象
3. 明确业务不变量
4. 设计聚合的公共接口（方法）

**输出**：聚合设计文档、代码框架

### Phase 7: 实体与值对象设计
**时长**：2 小时

为每个实体和值对象：
1. 确定是实体还是值对象
2. 定义属性和行为
3. 实现相等性和验证
4. 代码示例

**使用 Agent**：domain-modeler
```
Prompt: 设计这个聚合中的实体和值对象。
提供：
- 标识策略
- 值对象的不可变性
- 领域行为实现
```

**输出**：实体和值对象设计

### Phase 8: 领域服务与事件设计
**时长**：2 小时

1. 识别跨聚合逻辑（领域服务）
2. 设计领域事件
3. 定义事件发布
4. 规划事件订阅者

**输出**：领域服务定义、事件清单

### Phase 9: 资源库与应用服务
**时长**：2 小时

1. 设计资源库接口
2. 定义应用服务
3. 规划事务边界
4. 规划跨聚合协调

**输出**：资源库接口、应用服务框架

### Phase 10: 测试策略设计
**时长**：1 小时

1. 聚合的单元测试
2. 聚合间集成测试
3. 端到端用例测试
4. 测试用例示例

**输出**：测试计划、示例测试

### Phase 11: 代码实现与验证
**时长**：可变

1. 实现领域模型
2. 编写测试
3. 验证不变量
4. 重构和优化

## 建模方法选择

### --modeling-method（必需）

**event-storming**（推荐）
```
--modeling-method=event-storming
```
- 从业务事件出发
- 识别命令和聚合
- 适合团队协作

**four-color**
```
--modeling-method=four-color
```
- 四色建模法
- 详细的对象分类
- 适合复杂域

**requirements-first**
```
--modeling-method=requirements-first
```
- 从需求文档出发
- 传统的分析方法

## 执行参数

### 必需参数
- `--subdomain`: 要建模的子域名称
- `--modeling-method`: 建模方法（event-storming/four-color）

### 可选参数
- `--tech-stack`: 实现技术栈（Java/C#/Python）
- `--include-examples`: 是否生成代码示例（默认 true）
- `--depth`: 详细程度（basic/standard/detailed）

## 成功标准

- [ ] 识别了所有关键聚合
- [ ] 每个聚合的边界清晰
- [ ] 业务不变量被明确保护
- [ ] 所有命令都对应聚合方法
- [ ] 所有重要事件都被定义
- [ ] 资源库接口已设计
- [ ] 有完整的代码框架
- [ ] 有测试用例示例

## 输出物

- `aggregates.md` - 聚合定义和设计

- `domain-events.md` - 领域事件定义
- `domain-services.md` - 领域服务设计
- `test-cases.md` - 测试用例示例
- 代码框架（按选定的技术栈）
