# 限界上下文识别检查清单

使用这个清单来验证你识别的限界上下文是否合理。

## 上下文基本信息

上下文名称：____________
业务职责：____________
主要概念：____________

## 业务合理性检查

- [ ] **业务价值清晰**
  - 这个上下文代表了什么业务价值？
  - 业务能否用一句话描述这个上下文的目标？

- [ ] **概念一致**
  - 这个上下文内的关键概念是否有一致的含义？
  - 是否存在在不同地方有不同含义的概念？
  - 如果存在，是否需要重新划分边界？

- [ ] **完整性充分**
  - 完成这个上下文的业务价值是否需要依赖其他上下文？
  - 依赖是否合理？
  - 是否有"最小完备"的感觉？

- [ ] **边界清晰**
  - 这个上下文包含什么？
  - 这个上下文不包含什么？
  - 边界线在哪里？

- [ ] **与其他上下文的关系清晰**
  - 哪些上下文是下游消费者？
  - 哪些上下文是上游提供者？
  - 关系类型是什么（依赖、合作、独立）？

## 团队组织检查

- [ ] **团队规模合理**
  - 一个 7-10 人的特性团队能否完整负责这个上下文？
  - 还是需要多个团队？

- [ ] **团队技能需求清晰**
  - 需要什么技能？
  - 现有团队是否具备这些技能？
  - 学习曲线如何？

- [ ] **团队间通信需求**
  - 这个上下文需要与多少其他上下文频繁沟通？
  - 是否可能造成团队间大量协调？
  - 康威定律是否支持这个划分？

- [ ] **团队自主性**
  - 这个上下文的团队能否独立完成大多数工作？
  - 是否需要经常等待其他团队？

## 技术可行性检查

- [ ] **数据模型独立**
  - 这个上下文的数据是否可以独立存储？
  - 是否需要共享表或数据库？
  - 数据一致性需求是什么？

- [ ] **技术栈灵活**
  - 这个上下文是否可以采用不同的技术栈？
  - 现有技术选型是否可以？
  - 未来需要灵活改变吗？

- [ ] **集成清晰**
  - 与其他上下文的通信方式是什么？
  - 接口和契约清晰吗？
  - 异步还是同步通信？

- [ ] **部署独立性**
  - 这个上下文能否独立部署？
  - 部署顺序有依赖吗？
  - 回滚是否独立？

## 自治要素检查

### 最小完备
- [ ] 完成核心业务价值所需的功能都包含了吗？
- [ ] 是否有不必要的功能被引入？
- [ ] 依赖其他上下文是否合理和必要？

### 自我履行
- [ ] 这个上下文能否自行决定是否执行请求？
- [ ] 是否掌握了决策所需的信息？
- [ ] 是否存在"被迫服从"其他上下文的情况？

### 稳定空间
- [ ] 外部变化如何影响这个上下文？
- [ ] 是否有清晰的防护边界？
- [ ] 内部空间是否足够稳定？

### 独立进化
- [ ] 对外暴露的接口是否稳定？
- [ ] 内部实现可以随意改变吗？
- [ ] 是否考虑了版本兼容性？

## 边界冲突检查

- [ ] 是否有功能在这个上下文和另一个上下文都适合？
- [ ] 是否有概念在多个上下文间有不同含义？
- [ ] 是否有重复的代码或数据？
- [ ] 是否有悬空的功能不属于任何上下文？

## 设计决策记录

**决策**：为什么选择这样的边界划分？

**备选方案**：考虑过其他划分方案吗？为什么没选？

**风险**：这个边界划分有什么潜在风险？

**演化计划**：未来可能需要调整这个边界吗？
