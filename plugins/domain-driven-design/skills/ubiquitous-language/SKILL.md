# 统一语言

统一语言是 DDD 的基础。它是技术团队与业务人员共同理解的、用于描述业务领域的一致术语和概念。

## When to Use This Skill

- 新项目或新领域启动
- 团队对业务术语理解不一致
- 需要与非技术利益相关者沟通
- 准备向代码写术语
- 解决跨团队术语冲突
- 管理术语演化

## Core Concepts

### 1. 统一语言的两个方面

#### A. 统一的领域术语

精确的、有定义的业务术语，业务和技术团队都理解并使用。

**建立方法**：
1. 与领域专家讨论关键概念
2. 用清晰、精确的定义记录每个术语
3. 识别同义词和歧义词
4. 为技术术语确定英文对应
5. 创建和维护术语表

**示例术语**：
```
术语：订单（Order）
定义：顾客购买商品的请求，包含商品清单、收货地址和支付方式
同义词：购单（过时）
相关概念：订单项、支付、配送
英文：Order
不是：购物车、支付记录、发票
```

#### B. 领域行为描述

用统一语言描述业务过程和规则。

**特征**：
- 从领域角度而非实现角度描述
- 使用统一语言的术语
- 强调动作的精确性
- 突出相关的领域概念

**示例**：
```
❌ 不好的描述
管理订单库存

✓ 好的描述
为订单预留库存：
- 输入：订单 ID、商品清单
- 处理：检查每件商品的库存数量
- 规则：库存必须≥订单数量；不能超卖
- 输出：预留成功或失败通知
- 事件：库存已预留或预留失败
```

### 2. 术语表的内容

一个完整的术语表应该包含：

```
术语：[中文术语]
定义：[精确的业务定义]
英文：[标准英文翻译]
同义词：[相关名称]
反义词：[对立概念]
相关术语：[相关的其他术语]
示例：[具体例子]
背景：[为什么这个术语重要]
英文代码示例：
  class [EnglishName] {
    // 如何在代码中使用
  }
上下文：[在哪些限界上下文中使用]
版本：[术语版本和变更历史]
```

### 3. 语言的三个层次

#### 应该使用统一语言的地方

1. **文档和需求**
   - 需求文档中明确使用术语表的术语
   - 需求描述应该用领域语言

2. **代码**
   - 类名、方法名、字段名都应该用统一语言
   - 代码应该"读起来"像业务语言
   ```java
   // ✓ 好的代码
   order.confirmPayment(paymentId);
   inventory.reserveFor(order);

   // ❌ 坏的代码
   order.processTransaction(id);
   inv.allocate(ord);
   ```

3. **对话**
   - 所有讨论都应该用统一术语
   - 如果出现新术语，立即讨论和定义
   - 不用新术语代替已定义的术语

## Patterns & Practices

### 术语提取工作坊

**目标**：从领域专家提取关键术语和概念

**步骤**：
1. 列出业务流程中的主要活动
2. 每个活动涉及什么对象和概念？
3. 这些概念有标准名称吗？
4. 业务人员如何用本地语言称呼它们？
5. 技术团队的理解是否相同？

### 术语表维护

**更新流程**：
1. 提出新术语或修改建议
2. 召集相关人员讨论
3. 达成一致
4. 记录决定和理由
5. 通知所有相关团队
6. 更新所有代码和文档

**版本管理**：
- 每个重大变更增加版本号
- 记录变更时间和原因
- 保留历史，便于追踪

### 冲突解决

**常见冲突**：

情景：前端说'用户'是已登录用户，后端说'用户'包括游客

**解决步骤**：
1. 理解两个定义的差异
2. 识别业务上是否需要区分
3. 创建新的精确术语
4. 定义术语的英文对应
5. 更新文档和代码

**结果**：
```
术语调整：
- 已登录用户 → Authenticated User
- 游客 → Visitor
- 用户账户 → User Account
```

## Best Practices

1. **术语要精确**
   - 避免模糊词（管理、处理、维护）
   - 用具体、有意义的词汇
   - 如果难以命名，说明理解还不够深

2. **双语术语表**
   - 记录中文和英文
   - 确保代码的英文术语与表一致
   - 混淆的中英术语是常见的 bug 来源

3. **术语在代码中一致**
   - Code review 检查术语使用
   - 自动化检查（如 linter）
   - 重构时保持术语一致

4. **术语会演化**
   - 允许术语随着理解而改变
   - 有计划地引入新术语
   - 标记过时术语

5. **跨团队同步**
   - 定期同步术语变化
   - 多个团队使用相同定义
   - 记录上下文特定的术语变化
