# 完整4+1架构设计工作流 (41view-Complete-Workflow Command)

指导用户在8-12周内完成完整的4+1架构视图设计。

## 工作流概览

这是一个完整的、分阶段的架构设计过程，包括需求分析、5个视图设计、视图整合、文档编写。

### 时间表
```
第1-2周：需求分析和架构约束
第3周：  场景视图设计
第4-5周：逻辑视图设计
第6-7周：开发视图设计
第8-9周：进程视图设计
第10-11周：物理视图设计
第12周： 视图整合、评审、文档
```

## Phase 1-2: 需求分析（1-2周）

### 关键活动

**1. 收集需求**
- [ ] 进行需求访谈（与产品、业务、技术团队）
- [ ] 整理功能需求清单
- [ ] 列出非功能需求（性能、可用性、安全）
- [ ] 识别业务和技术约束

**2. 定义架构约束**
- [ ] 技术栈选择（语言、框架、数据库）
- [ ] 团队规模和开发周期
- [ ] 预算和资源限制
- [ ] 合规和安全要求

**3. 分析关键指标**
- [ ] 用户规模和增长预期
- [ ] 并发量和QPS要求
- [ ] 可用性目标（99.9%? 99.95%?）
- [ ] 性能目标（响应时间、延迟）

**输出物**：
- 需求文档（需求和约束清单）
- 非功能需求规范（SLA）
- 架构约束列表

---

## Phase 3: 场景视图设计（1周）

### 关键活动

**1. 识别参与者**
- [ ] 列出所有参与者（最终用户、系统、外部服务）
- [ ] 为每个参与者定义角色
- [ ] 识别参与者间的交互模式

**2. 定义用例**
- [ ] 列出所有用例（建议15-30个）
- [ ] 为每个用例分配优先级
- [ ] 识别关键用例（高优先级、高复杂度）

**3. 编写关键用例的详细流程**
- [ ] 主流程描述
- [ ] 替代流程
- [ ] 异常处理
- [ ] 非功能需求

**4. 绘制用例图**
- [ ] 使用PlantUML创建用例图
- [ ] 标注参与者和系统边界
- [ ] 标注用例间的关系（include, extend）

**推荐使用Agent**：`/scenario-view-architect`

**输出物**：
- PlantUML用例图
- 用例定义文档（20-30个用例）
- 关键用例的详细描述（5-10个）

---

## Phase 4: 逻辑视图设计（2周）

### 关键活动

**1. 领域建模**
- [ ] 从用例中提取业务对象
- [ ] 分类为实体、值对象、聚合
- [ ] 定义对象的生命周期

**2. 设计类结构**
- [ ] 为每个业务对象设计类
- [ ] 定义属性和方法
- [ ] 指定约束和不变性

**3. 定义类间关系**
- [ ] 分析关联、聚合、组合关系
- [ ] 指定多重性
- [ ] 避免循环依赖

**4. 设计服务接口**
- [ ] 定义业务服务接口
- [ ] 指定方法签名
- [ ] 定义异常

**5. 创建类图**
- [ ] 使用PlantUML绘制类图
- [ ] 包括类、属性、方法、关系
- [ ] 标注多重性

**推荐使用Agent**：`/logical-view-architect`

**输出物**：
- PlantUML类图
- 类定义文档（所有关键类）
- 设计决策记录（为什么这样设计）

---

## Phase 5: 开发视图设计（2周）

### 关键活动

**1. 模块分解**
- [ ] 识别功能领域
- [ ] 为每个领域创建一个模块
- [ ] 定义模块边界和职责

**2. 包结构设计**
- [ ] 设计包的层次结构
- [ ] 按功能领域和分层组织
- [ ] 建立clear目录结构

**3. 分层架构设计**
- [ ] 确定系统的分层（通常4-5层）
- [ ] 定义每层的职责
- [ ] 管理层间的依赖

**4. 依赖管理**
- [ ] 验证单向依赖
- [ ] 检查无循环依赖
- [ ] 设计模块间的通信接口

**5. 创建图表**
- [ ] 绘制组件图
- [ ] 绘制包图
- [ ] 标注模块依赖

**推荐使用Agent**：`/development-view-architect`

**输出物**：
- PlantUML组件图和包图
- 包结构说明
- 模块依赖关系清单
- 分层架构说明

---

## Phase 6: 进程视图设计（1-2周）

### 关键活动

**1. 并发分析**
- [ ] 识别高并发操作
- [ ] 分析同时发生的活动
- [ ] 评估并发量（QPS、TPS）

**2. 关键场景设计**
- [ ] 选择3-5个关键场景
- [ ] 设计每个场景的执行流程
- [ ] 标注同步和异步点

**3. 序列图设计**
- [ ] 为每个关键场景绘制序列图
- [ ] 标注消息和调用
- [ ] 标注并行活动

**4. 活动图设计**
- [ ] 为复杂流程绘制活动图
- [ ] 标注分支、循环、同步

**5. 性能优化**
- [ ] 分析关键路径
- [ ] 识别性能瓶颈
- [ ] 提出优化建议

**推荐使用Agent**：`/process-view-architect`

**输出物**：
- PlantUML序列图（3-5个）
- PlantUML活动图（1-2个）
- 并发设计说明
- 性能指标和优化建议

---

## Phase 7: 物理视图设计（1-2周）

### 关键活动

**1. 部署需求分析**
- [ ] 确定部署单元
- [ ] 评估规格需求（CPU、内存、存储）
- [ ] 确定副本数量

**2. 网络拓扑设计**
- [ ] 设计网络分层（DMZ、应用区、数据区）
- [ ] 定义防火墙规则
- [ ] 规划冗余和备份

**3. 高可用设计**
- [ ] 设计无单点故障
- [ ] 定义故障转移机制
- [ ] 规划数据备份和恢复

**4. 技术选型**
- [ ] 选择部署平台（虚拟机、容器、无服务器）
- [ ] 选择云提供商或自建
- [ ] 定义监控和告警

**5. 成本估算**
- [ ] 计算基础设施成本
- [ ] 估计运维成本
- [ ] 验证是否在预算内

**6. 部署图设计**
- [ ] 绘制部署图
- [ ] 标注物理节点和连接
- [ ] 标注高可用配置

**推荐使用Agent**：`/physical-view-architect`

**输出物**：
- PlantUML部署图
- 网络拓扑说明
- 高可用方案文档
- 成本估算报告
- 监控方案说明

---

## Phase 8: 视图整合和评审（1-2周）

### 关键活动

**1. 视图一致性检查**
- [ ] 验证场景→逻辑的对齐
- [ ] 验证逻辑→开发的对齐
- [ ] 验证开发→进程的对齐
- [ ] 验证进程→物理的对齐

**2. 冲突识别和解决**
- [ ] 识别视图间的冲突或不一致
- [ ] 分析冲突的根本原因
- [ ] 评估各个解决方案
- [ ] 做出决策并记录ADR

**3. 整体架构评审**
- [ ] 完整性评审（是否覆盖所有需求）
- [ ] 一致性评审（视图间是否一致）
- [ ] 合理性评审（是否有更好的方案）
- [ ] 可行性评审（团队能否实现）

**4. 架构文档编写**
- [ ] 编写完整的架构文档
- [ ] 创建ADR（架构决策记录）
- [ ] 编写视图对齐报告

**推荐使用Agent**：`/41view-master-architect`

**输出物**：
- 对齐检查报告
- 架构决策记录（5-10个ADR）
- 完整的架构文档
- 评审报告和改进建议

---

## Phase 9: 文档完善和实施计划（1周）

### 关键活动

**1. 架构文档完善**
- [ ] 系统概述
- [ ] 需求和约束
- [ ] 5个视图的完整描述
- [ ] 非功能需求规范

**2. 实施指南编写**
- [ ] 开发环境设置
- [ ] 代码结构和规范
- [ ] 开发流程和规则

**3. 部署指南编写**
- [ ] 部署步骤
- [ ] 监控和告警
- [ ] 灾难恢复流程

**4. 实施路线图**
- [ ] 确定实施阶段（通常3-4个阶段）
- [ ] 每个阶段的关键里程碑
- [ ] 资源和时间估算

**输出物**：
- 完整的架构设计文档
- 实施指南
- 部署指南
- 实施路线图

---

## 完整性检查清单

完成所有阶段后，进行最终检查：

### 需求覆盖
- [ ] 所有功能需求都被用例覆盖
- [ ] 所有非功能需求都有明确的设计体现
- [ ] 所有业务和技术约束都被考虑

### 5个视图完整
- [ ] 场景视图：完整的用例和场景
- [ ] 逻辑视图：完整的类和关系
- [ ] 开发视图：清晰的包结构和分层
- [ ] 进程视图：关键场景的流程和性能
- [ ] 物理视图：完整的部署设计

### 视图一致性
- [ ] 所有视图相互支撑
- [ ] 没有相互矛盾的设计
- [ ] 每个视图都能指导下一个视图

### 设计可实现性
- [ ] 使用的技术栈团队熟悉
- [ ] 资源和时间充足
- [ ] 没有不可克服的技术难题

### 文档完整
- [ ] 所有图表都符合规范
- [ ] 文档清晰易懂
- [ ] 有充分的例子和说明

---

## 后续步骤

架构设计完成后：
1. 组织团队培训和知识转移
2. 开始实施工作（按照实施路线图）
3. 定期审查设计和实施进展
4. 根据实施情况调整设计
