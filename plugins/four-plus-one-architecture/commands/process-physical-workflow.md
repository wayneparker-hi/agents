# 进程和物理视图快速工作流 (Process-Physical-Workflow Command)

针对已有代码结构，快速进行性能和部署优化的2-3周工作流。

## 工作流概览

这个工作流适用于已有基本的逻辑和开发视图，需要进行性能优化和部署规划的项目。

### 时间表
```
第1周：进程视图设计（性能和并发分析）
第2周：物理视图设计（部署和高可用规划）
第3周：优化和完善（可选）
```

## 前提条件

✅ 已有清晰的开发视图：
- 完整的包结构
- 清晰的分层架构
- 定义好的模块依赖

✅ 已有非功能需求规范：
- 性能指标（QPS、响应时间）
- 可用性需求（可用率）
- 可扩展性需求（并发用户数）

## Week 1: 进程视图设计

### Day 1-2: 并发分析和关键场景识别

**任务**：分析并发需求，识别关键场景

```
分析内容：
1. 系统的并发模型
   - 日均用户/订单量
   - 高峰时期的QPS
   - 平均响应时间需求

2. 识别关键场景（3-5个）
   - 高并发场景（查询、下单）
   - 可靠性关键场景（支付、转账）
   - 复杂流程（多步骤、多参与者）

示例计算：
  日均订单：1000万
  工作时间：8小时
  平均QPS：1000万 / (8*3600) = 347/秒
  高峰QPS：347 * 5 = 1735/秒
  所需线程数：1735 * 0.1秒 = 174个
```

**推荐使用Agent**：`/process-view-architect`

**输出**：
- 并发分析报告
- 关键场景清单
- 性能指标目标（P50, P95, P99）

---

### Day 3-4: 序列图和活动图设计

**任务**：为关键场景绘制序列图和活动图

```
对每个关键场景：
1. 标注参与者（用户、服务、外部系统）
2. 标注消息和调用顺序
3. 标注同步和异步点
4. 标注可以并行的操作

示例下单场景：
  消费者 → OrderService → InventoryService → DB
  同时：OrderService → 缓存（查询库存）
  异步：OrderService → MQ → 推送服务
```

**输出**：
- PlantUML序列图（3-5个）
- PlantUML活动图（1-2个）
- 每个图的详细说明

---

### Day 5: 性能优化建议

**任务**：分析关键路径，提出优化建议

```
优化技巧：
1. 缓存
   - 哪些数据可以缓存？
   - 缓存过期策略是什么？

2. 异步处理
   - 哪些操作可以异步？
   - 使用消息队列还是事件驱动？

3. 数据库优化
   - 哪些查询需要优化？
   - 需要哪些索引？

4. 并发模型
   - 线程池大小
   - 连接池配置
   - 其他资源池
```

**输出**：
- 性能瓶颈分析
- 优化建议清单（优先级排序）
- 预期的性能改进

---

## Week 2: 物理视图设计

### Day 1-2: 部署架构设计

**任务**：规划系统的部署拓扑

```
确定：
1. 部署单元
   - Web服务器 / API网关
   - 应用服务器（按服务）
   - 数据库
   - 缓存
   - 消息队列

2. 规格需求
   - CPU、内存、存储
   - 网络带宽

3. 副本数量
   - 基于性能需求
   - 基于可用性需求

示例计算：
  高峰QPS: 1735/秒
  单个实例容量: 500 QPS
  所需实例数: 1735 / 500 = 4个（向上取整）
  考虑容错: 4 + 1冗余 = 5个实例
```

**推荐使用Agent**：`/physical-view-architect`

**输出**：
- 部署需求清单
- 实例规格定义
- 部署拓扑图（初稿）

---

### Day 3-4: 高可用和网络设计

**任务**：设计高可用方案和网络拓扑

```
高可用设计：
1. 数据库
   - 主从复制 / 主主复制
   - 自动转移
   - 备份策略

2. 应用服务
   - 多实例部署
   - 负载均衡
   - 故障检测和转移

3. 缓存和MQ
   - 集群部署
   - 持久化配置
   - 数据同步

网络拓扑：
  互联网 → CDN → LB → DMZ(网关) → 应用区 → 数据区
                            ↓
                       防火墙隔离
```

**输出**：
- 高可用方案文档
- 网络拓扑图
- 防火墙规则清单
- 故障转移流程

## 常见问题

**Q: 如何确定需要多少个实例？**
A: 根据以下因素：
1. 高峰QPS和单个实例容量
2. 故障转移需要的冗余（通常+1-2个）
3. 滚动更新需要的容量

示例：
```
高峰QPS: 1000
单实例容量: 200 QPS
基础实例数: 1000/200 = 5个
+故障转移冗余: +1 = 6个
+滚动更新缓冲: +1 = 7个
```

**Q: 如何选择缓存策略？**
A: 根据数据特性：
- 热点数据（频繁访问）→ 缓存
- 准实时数据（可容忍延迟）→ 缓存+定期更新
- 实时数据（不能有延迟）→ 不缓存或缓存+后台更新

**Q: 物理视图设计需要多细致？**
A: 足够指导部署和运维。包括：
- 各个组件的规格和数量
- 网络拓扑和安全配置
- 高可用和灾难恢复方案
- 监控和告警配置

不需要精确到网络丢包率或磁盘IOPS（除非有特殊需求）。
