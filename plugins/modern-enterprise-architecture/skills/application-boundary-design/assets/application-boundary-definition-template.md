## 核心业务概念

### 主要数据实体

```
实体名称        │ 描述                │ 所有权状态
─────────────────┼────────────────────┼────────────────
Order            │ 订单信息             │ 拥有
OrderItem        │ 订单条目             │ 拥有
OrderStatus      │ 订单状态             │ 拥有
Customer         │ 顾客信息             │ 引用（用户应用）
Product          │ 产品信息             │ 引用（商品应用）
Payment          │ 支付信息             │ 引用（支付应用）
```

### 核心业务流程

```
流程名称：订单创建流程

参与者：
  ├─ 顾客
  ├─ 订单应用
  ├─ 库存应用
  └─ 支付应用

步骤：
  1. 顾客发起订单创建请求
  2. 订单应用验证顾客信息
  3. 订单应用调用库存应用检查库存
  4. 库存应用返回库存情况
  5. 如果库存充足，订单应用创建订单
  6. 订单应用发送事件"OrderCreated"
  7. 支付应用监听事件，准备支付
  8. 订单应用返回订单 ID 给顾客

关键决策点：
  ├─ 库存不足时：拒绝订单还是部分订单？
  ├─ 支付失败时：订单状态如何变化？
  └─ 顾客取消时：如何补偿？
```

## 数据架构

### 应用数据所有权

```
应用拥有的数据：
  ├─ Order 表
  │  ├─ order_id (PK)
  │  ├─ customer_id
  │  ├─ order_date
  │  ├─ total_amount
  │  └─ status
  │
  ├─ OrderItem 表
  │  ├─ order_item_id (PK)
  │  ├─ order_id (FK)
  │  ├─ product_id
  │  ├─ quantity
  │  └─ unit_price
  │
  └─ OrderStatus 表
     ├─ status_id (PK)
     ├─ order_id (FK)
     ├─ status
     ├─ changed_at
     └─ changed_by

应用引用的数据：
  ├─ customer_id（来自用户应用）
  └─ product_id（来自商品应用）

数据一致性要求：
  □ Order 和 OrderItem 必须强一致（同一应用）
  □ Order 和 Customer 最终一致（跨应用）
  □ Order 和 Product 最终一致（跨应用）
```

### 数据保留和隐私

```
数据保留策略：
  ├─ 订单数据保留：7 年（合法要求）
  ├─ 订单日志保留：3 年
  ├─ 用户偏好保留：2 年
  └─ 个人信息删除：用户请求后 30 天

隐私要求：
  ├─ 订单金额：仅本应用和财务应用可见
  ├─ 顾客地址：仅物流应用和订单应用可见
  └─ 支付信息：支付应用处理，订单应用不存储
```

## 对外接口（API）

### HTTP REST API

```
基础 URL：https://api.example.com/v1

API 1：创建订单
  POST /orders

  请求：
  {
    "customerId": "CUST123",
    "items": [
      {
        "productId": "PROD456",
        "quantity": 2,
        "unitPrice": 100
      }
    ],
    "shippingAddress": "..."
  }

  响应（201 Created）：
  {
    "orderId": "ORD789",
    "status": "CREATED",
    "totalAmount": 200,
    "createdAt": "2024-01-15T10:30:00Z"

  GET /orders/{orderId}

    "orderId": "ORD789",
    "status": "CONFIRMED",

    "totalAmount": 200,
    "createdAt": "2024-01-15T10:30:00Z",
    "confirmedAt": "2024-01-15T10:31:00Z"
  }

API 3：取消订单
  DELETE /orders/{orderId}

  响应（200）：
  {
    "orderId": "ORD789",
    "status": "CANCELLED",
    "cancelledAt": "2024-01-15T10:35:00Z"
  }

...（列出所有对外 API）
```

## 依赖关系

### 应用间依赖

```
应用依赖关系图：

  [订单应用]
    ├─→ [库存应用] (同步, 必须)
    │   └─ 调用：检查库存、预留库存
    │   └─ 频率：每个订单创建时
    │   └─ SLA：< 200ms
    │
    ├─→ [支付应用] (异步, 必须)
    │   └─ 监听：PaymentProcessed, PaymentFailed
    │   └─ 发布：OrderCreated, OrderConfirmed
    │   └─ 频率：每个订单创建/取消时
    │
    └─→ [通知应用] (异步, 可选)
        └─ 发布：OrderCreated, OrderConfirmed, OrderCancelled
        └─ 频率：每个状态变化时

依赖的外部系统：
  ├─ 用户应用
  │  └─ 获取：顾客信息、权限检查
  │
  ├─ 商品应用
  │  └─ 获取：产品信息、价格
  │
  └─ 财务应用
     └─ 发送：订单金额用于对账

被依赖的应用：
  └─ （订单应用是被动的）

核心依赖（无此无法运行）：
  ├─ 库存应用（同步）
  └─ 支付应用（异步，可配置）

可选依赖（没有会降低体验但不影响核心）：
  └─ 通知应用（发送邮件/短信）
```

### 依赖协议

```
依赖协议 1：与库存应用的集成

调用方式：同步 HTTP REST
重试策略：失败 3 次，指数退避（1s, 2s, 4s）
超时设置：5 秒
断路器：连续失败 5 次后，60 秒内返回失败
降级方案：
  ├─ 如果库存应用不可用，订单可以进入 PENDING_INVENTORY 状态
  ├─ 异步重试库存预留
  └─ 超时 1 小时后自动取消订单

错误处理：
  ├─ 库存不足：返回 400 INSUFFICIENT_INVENTORY，订单取消
  ├─ 库存应用超时：返回 504，订单进入 PENDING_INVENTORY
  └─ 库存应用故障：降级处理（见上文）

数据格式：
  请求：
  {
    "productId": "PROD123",
    "quantity": 2,
    "reservationId": "RES789"
  }

  响应：
  {
    "reserved": true,
    "reservedQuantity": 2,
    "reservationId": "RES789"
  }

版本管理：
  当前版本：v1
  弃用时间：2024-12-31
  后继版本：v2（2024-06-01 推出）
  兼容性：v1 和 v2 并存期间兼容
```

## 性能和质量属性

### 性能要求

```
关键指标：

API 响应时间（P95）：
  ├─ 创建订单：< 500ms
  ├─ 查询订单：< 200ms
  ├─ 取消订单：< 300ms
  └─ 批量查询：< 1s

吞吐量：
  ├─ 正常时期：1000 req/s
  ├─ 高峰时期：5000 req/s
  └─ 突发峰值：10000 req/s

数据库性能：
  ├─ 查询响应时间：< 10ms
  ├─ 更新响应时间：< 20ms
  ├─ 批量操作：< 100ms

内存使用：
  ├─ 正常状态：< 500MB
  ├─ 峰值状态：< 1GB
  └─ 缓存大小：100MB
```

### 可靠性要求

```
可用性（SLA）：
  ├─ 核心功能（创建、查询订单）：99.95%
  ├─ 其他功能：99.9%
  ├─ 计划外维护：每月 1-2 小时
  └─ 允许停机时间：每月 < 22 分钟

容错能力：
  ├─ 单点故障恢复时间：< 1 分钟
  ├─ 数据库故障恢复：自动故障转移
  ├─ 网络故障：自动重试和降级
  └─ 级联故障：断路器保护

数据一致性：
  ├─ 核心数据：强一致（ACID）
  ├─ 跨应用数据：最终一致（5 分钟内）
  └─ 缓存数据：5 分钟过期
```

### 安全要求

```
认证：
  ├─ 所有 API 必须认证（JWT Token）
  ├─ Token 过期时间：1 小时
  └─ 刷新 Token 过期时间：7 天

授权：
  ├─ 用户只能查看自己的订单
  ├─ 管理员可以查看所有订单
  ├─ 只有订单所有者或管理员可以修改订单
  └─ 删除订单操作审计

数据加密：
  ├─ 传输层：TLS 1.2+
  ├─ 存储层：客户信息和支付信息加密
  └─ 密钥管理：定期轮换，KMS 管理

审计和监控：
  ├─ 所有订单操作记录日志
  ├─ 敏感信息（如支付金额）标记
  ├─ 异常操作告警
  └─ 日志保留 1 年
```
