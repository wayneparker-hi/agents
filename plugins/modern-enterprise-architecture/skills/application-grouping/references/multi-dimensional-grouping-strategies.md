# 应用分组方案对比与选择指南

本文档帮助您选择最适合的应用分组方案。

## 分组维度对比

### 维度 1：按业务域分组 vs 按技术分组

```
按业务域分组：
  优势：
    ✅ 业务人员易于理解
    ✅ 与产品和业务目标对齐
    ✅ 团队组织结构清晰
    ✅ 便于产品迭代

  劣势：
    ❌ 可能有跨领域的应用
    ❌ 技术栈可能混杂

按技术分组：
  优势：
    ✅ 运维管理统一
    ✅ 技术栈一致
    ✅ 知识复用高

  劣势：
    ❌ 业务人员难以理解
    ❌ 应用与产品目标关联不紧密

推荐：按业务域分组为主，辅以技术考虑
```

### 维度 2：按团队分组 vs 按功能分组

```
按团队分组（推荐）：
  - 团队和应用边界对齐
  - 责任明确，沟通成本低
  - 应用发展与团队成长一致

按功能分组：
  - 功能相似的应用放在一起
  - 可能导致多个团队共维一个应用
  - 容易产生冲突

结论：尽可能按团队分组
```

## 分组方案决策框架

```
您现在有多少个应用？

  < 5 个
    └─ 无需分组，直接分配给团队

  5-15 个
    ├─ 按业务域分组（推荐）
    │  └─ 2-3 个应用组
    │
    └─ 按战略重要性分层
       └─ 核心、支撑、平台三层

  15-30 个
    ├─ 混合分组方案
    │  ├─ 核心应用按业务域分组
    │  ├─ 支撑应用按技术分组
    │  └─ 平台应用单独为组
    │
    └─ 需要清晰的应用间依赖管理

  > 30 个
    ├─ 必须采用高度结构化的分组
    │  ├─ 第 1 级：按业务线（如购物、支付、物流）
    │  ├─ 第 2 级：按业务域（如订单、库存等）
    │  └─ 第 3 级：按功能（如查询、统计等）
    │
    └─ 建立应用治理体系
       └─ 应用目录、依赖管理、文档规范
```

## 应用分组协调机制

### 应用组间通信

```
推荐的协调方式：

关键路径（同步）：
  ├─ 订单组 → 库存组（查询库存）
  ├─ 订单组 → 支付组（创建支付单）
  └─ SLA：< 200ms

非关键路径（异步）：
  ├─ 订单组 → 通知组（发送邮件）
  ├─ 库存组 → 分析组（库存变更数据）
  └─ SLA：最终一致（< 5 分钟）

最小化跨组协调：
  └─ 如果两个组需要频繁协调（> 10 次/分钟）
     └─ 考虑合并这两个组
```

### 依赖管理

```
应用分组依赖矩阵模板：

应用组         │ 订单组 │ 库存组 │ 支付组
───────────────┼────────┼────────┼────────
订单组         │        │ 同步   │ 异步
库存组         │        │        │ 无
支付组         │        │        │

说明：
  同步：依赖较强，需要考虑版本协调
  异步：依赖较弱，通过事件驱动
  无：完全独立

最终状态应该是：
  └─ 大多数是无依赖或异步依赖
  └─ 最小化同步依赖
```

## 分组方案的评估清单

```
□ 方案的清晰性
  ├─ 能用 1 句话说明分组原则吗？
  ├─ 每个应用组的职责清晰吗？
  └─ 新成员能快速理解方案吗？

□ 团队对齐
  ├─ 是否存在一个应用多个团队维护？
  ├─ 是否存在一个团队维护多个无关应用？
  ├─ 团队规模是否合理（3-5 人）？
  └─ 团队的技能是否匹配？

□ 可操作性
  ├─ 部署是否清晰（谁负责）？
  ├─ 发布流程是否定义好？
  ├─ 监控和告警方案清晰吗？
  └─ 应急响应流程确定了吗？

□ 可演进性
  ├─ 当应用数增加时，方案还能扩展吗？
  ├─ 当组织调整时，方案能调整吗？
  ├─ 是否为微服务化预留空间？
  └─ 是否支持逐步演进？

□ 成本
  ├─ 应用间通信成本如何？
  ├─ 运维成本如何？
  ├─ 跨组协调成本如何？
  └─ 总成本是否合理？
```

## 最佳实践

```
1. 从简单开始
   ❌ 初期就建立复杂的分组体系
   ✅ 从简单的业务域分组开始

2. 与组织结构对齐
   ❌ 应用分组与团队结构不匹配
   ✅ 一个应用组对应一个小团队

3. 定期评估
   ❌ 分组方案一成不变
   ✅ 每个季度评估是否仍然合适

4. 文档化和沟通
   ❌ 分组方案只在头脑中
   ✅ 明确的文档和团队认同

5. 清晰的 API 契约
   ❌ 应用组间通过代码级别的耦合
   ✅ 明确定义 API 和通信协议
```
