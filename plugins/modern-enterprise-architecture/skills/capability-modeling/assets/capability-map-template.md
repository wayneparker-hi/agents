# 能力地图设计模板

## 能力地图的目的

能力地图是一个可视化工具，用于：
1. 明确显示组织的所有业务能力
2. 识别能力之间的关系和依赖
3. 发现重复和空缺
4. 规划技术投资
5. 指导组织结构设计

---

## 模板：三层能力地图

### 填写说明

```
L1 业务域：最粗粒度，通常 3-8 个
  - 覆盖整个公司或事业部的主要业务领域
  - 例：电商公司的订单域、库存域、支付域

L2 业务能力：中等粒度，L1 下通常 5-10 个
  - 支持某个业务流程或用户目标的能力
  - 例：订单域下的订单创建、订单查询、订单处理

L3 技术组件：细粒度，L2 下通常 2-5 个
  - 实现 L2 能力的技术构件
  - 例：订单创建能力由 OrderValidator、PriceCalculator 等组件实现
```

## 跨域依赖地图

### 依赖关系

```
订单域 ↓ (需要)
  └─ 库存检查
     ↑ (提供者)
    库存域

订单域 ↓ (需要)
  └─ 支付处理
     ↑ (提供者)
    支付域

订单域 ↓ (需要)
  └─ 用户查询
     ↑ (提供者)
    用户域

发货管理 ↓ (需要)
  ├─ 订单查询 (订单域)
  ├─ 库存更新 (库存域)
  └─ 用户地址 (用户域)

物流跟踪 ↓ (需要)
  └─ 订单查询 (订单域)
```

## 能力成熟度评估

### 成熟度模型

```
成熟度 1：特定性 (Ad-hoc)
  - 能力不成体系
  - 实现方式混乱
  - 无清晰的接口

成熟度 2：受管理 (Managed)
  - 能力有文档
  - 实现相对一致
  - 有初步的接口定义

成熟度 3：已定义 (Defined)
  - 能力有清晰定义
  - 接口规范化
  - 有完整的文档
  - 有测试覆盖

成熟度 4：量化管理 (Measured)
  - 有度量指标
  - 性能可预测
  - 定期优化

成熟度 5：优化 (Optimized)
  - 持续改进
  - 自动化程度高
  - 最佳实践内化
```

## 关键建议

1. **定期更新**：每个季度评审和更新能力地图
2. **跨团队对齐**：让所有团队都理解整体的能力地图
3. **识别空缺**：查看是否有重要的能力没有实现
4. **检测重复**：查看是否有重复实现的能力
5. **规划投资**：根据能力地图规划技术投资和人力分配
6. **建立治理**：有专人负责维护和演进能力地图
