# 数据分层实施检查清单

## 目的

本检查清单帮助数据架构师和建模师系统地规划和实施数据分层架构。

---

## 第一部分：分层策略确定

### 1.1 选择分层模式

```
□ 了解现有系统的数据流
  ├─ 业务系统类型（OLTP/OLAP/混合）
  ├─ 数据量规模
  ├─ 用户数量和查询模式
  ├─ 现有数据系统清单

□ 确定分层深度
  ├─ [ ] 3 层（ODS → DW → ADS）用于简单场景
  ├─ [ ] 5 层（ODS → DIM + FACT + AGG → ADS）用于复杂场景
  ├─ [ ] 自定义分层（根据具体需求）

□ 确定各层的职责
  ├─ ODS 层：原始数据保存、初级清洗
  ├─ DIM 层：维度数据管理
  ├─ FACT 层：事实数据存储
  ├─ AGG 层：聚合数据加速
  ├─ ADS 层：应用服务数据

□ 明确分层优势和约束
  ├─ 存储成本
  ├─ 计算成本
  ├─ 维护复杂度
  ├─ 数据延迟目标
```

```

  ├─ 数据库类型（MySQL/Oracle/MongoDB）

  ├─ 数据量规模

□ 评估数据源特性
  ├─ 是否有时间戳字段？□ 有 □ 无
  ├─ 是否支持增量抽取？□ 支持 □ 不支持
  ├─ 是否有删除操作的记录？□ 有 □ 无
  ├─ 最大延迟容忍度：___ 小时
  ├─ 数据质量评分（1-10）：___

□ 确定抽取策略
  ├─ [ ] 全量初始加载 + 增量更新
```
