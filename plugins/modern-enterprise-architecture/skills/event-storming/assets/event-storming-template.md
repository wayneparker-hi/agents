## 工作坊议程

### 第 1 部分：准备和引导（15分钟）

⏱️ **时间**: 0:00 - 0:15

**目标**: 确保所有参与者理解 Event Storming 的方法

**活动**:
1. **介绍方法** (5分钟)
   - 解释核心概念：事件、命令、聚合、外部系统
   - 强调游戏规则：
     - 快速记录，不评判
     - 一个事件一张便签
     - 重点优先
     - 疑问用"?"标记

2. **展示示例** (8分钟)
   - 用与参与者相关的业务示例
   - 展示如何记录事件、命令等
   - 回答初步问题

3. **明确范围** (2分钟)
   - 确认本次的业务范围
   - "我们聚焦在 XXX 流程"

### 第 2 部分：事件风暴（45分钟）

⏱️ **时间**: 0:15 - 1:00

**目标**: 识别所有关键的业务事件

**流程**:
```
时间线 →
|
[事件 1] → [事件 2] → [事件 3] → ... → [最终事件]
```

**主持人指导**:
- "在我们的业务中，会发生哪些重要的事件？"
- "接下来会发生什么？"
- "这个事件会触发什么？"

**参与者活动**:
- 在黄色便签上写下事件
- 用**过去式**命名（"订单已下单" 不是 "下单"）
- 按时间顺序贴在白板上

**示例**（电商订单流程）:
```
商品已浏览 → 商品已添加购物车 → 订单已下单 →
支付已完成 → 库存已扣除 → 发货已确认 →
包裹已发出 → 包裹已送达 → 评价已提交
```

**检查清单**:
- [ ] 事件覆盖了整个流程
- [ ] 事件按时间顺序排列
- [ ] 用了过去式命名
- [ ] 每个事件是独立的（不是多个事件的组合）

### 第 3 部分：补充命令和策略（30分钟）

⏱️ **时间**: 1:00 - 1:30

**目标**: 识别触发这些事件的操作和自动处理

#### 3A. 补充命令 (15分钟)

**主持人引导**:
- "什么操作会触发这些事件？"
- "是用户操作还是系统自动触发？"

**活动**:
- 在每个事件的**左边**贴蓝色便签（命令）
- 命令用**祈使式**命名（"下单"、"确认支付"）

**示例**:
```
浏览商品 → [商品已浏览]
添加购物车 → [商品已添加购物车]
下单 → [订单已下单]
```

#### 3B. 补充策略和外部系统 (15分钟)

**主持人引导**:
- "这个事件发生后会自动触发什么？"
- "需要与哪些外部系统交互？"

**活动**:
- 在事件**右边**贴红色便签（策略/自动操作）
- 外部系统用**橙色**便签标记

**示例**:
```
[订单已下单] →
  红: "自动发送确认邮件" → 橙: 邮件系统
  红: "扣库存" → 库存系统
  红: "生成支付订单" → 支付网关
```

**检查清单**:
- [ ] 每个事件都有触发的命令
- [ ] 识别了关键的自动处理逻辑
- [ ] 标记了所有外部系统的依赖

### 第 4 部分：识别聚合（30分钟）

⏱️ **时间**: 1:30 - 2:00

**目标**: 划定数据一致性的边界

**主持人引导**:
- "哪些事件和命令必须紧耦合，保持一致性？"
- "这些对象应该由一个实体管理，还是分开管理？"

**活动**:
1. 用虚线框圈出相关的事件和命令组
2. 给每个框取名（聚合名称）
3. 标记聚合根

**示例**:
```
┌─ 购物车聚合 ────────────────────────┐
│ 浏览商品 → [商品已浏览]            │
│ 添加购物车 → [商品已添加购物车]    │
│ 更新数量 → [数量已更新]             │
│ 清空购物车 → [购物车已清空]         │
└─────────────────────────────────────┘

┌─ 订单聚合 ────────────────────────────┐
│ 下单 → [订单已下单]                  │
│ 选择收货地址 → [地址已选择]          │
│ 确认订单 → [订单已确认]              │
│ 确认支付 → [支付已确认]              │
└───────────────────────────────────────┘
```

**检查清单**:
- [ ] 聚合的边界清晰
- [ ] 聚合内的事件相关且需要一致性
- [ ] 聚合间通过事件通信（不直接引用）

### 第 5 部分：发现问题（20分钟）

⏱️ **时间**: 2:00 - 2:20

**目标**: 标记需要进一步讨论的问题

**主持人指导**:
- "有没有不清楚或有争议的地方？"
- "这个流程在不同情况下会怎么样？"
- "失败的情况怎么处理？"

**记录方式**:
- 用粉色便签贴"?"标记疑问
- 用绿色便签标记"可变点"
- 列出问题清单，指定所有者

**常见问题示例**:
```
❓ 支付失败后怎么办？重试几次？
❓ 库存不足时的处理流程是什么？
🔄 VIP 用户和普通用户的流程有什么区别？
🔄 国内订单和国际订单的发货流程不同
⚠️ 发货后，如果用户不确认收货，多久才算确认？
```

### 第 6 部分：总结和审视（10分钟）

⏱️ **时间**: 2:20 - 2:30

**目标**: 确保流程逻辑一致

**活动**:
1. **从头走一遍**：按事件顺序，确保流程连贯
2. **检查覆盖度**：是否遗漏了重要的事件或聚合
3. **记录输出物**：拍照或用手机录像，便于后续还原

**检查清单**:
- [ ] 整个流程从开始到结束都清楚
- [ ] 所有事件都有命令和聚合
- [ ] 没有明显的逻辑漏洞
- [ ] 已识别的问题都有所有者和跟进计划

## 工作坊主持人的技巧

### 营造积极的氛围
- ✅ 欢迎所有想法，"没有坏主意"
- ✅ 经常说"谢谢"和"很好的观点"
- ✅ 避免批判或否定

### 保持节奏
- ✅ 不要陷入细节讨论，标记为问题，之后讨论
- ✅ 如果讨论超过 5 分钟，说"让我们标记这个问题，继续"
- ✅ 定时提醒（使用计时器）

### 确保参与
- ✅ 请每个角色的代表都发言
- ✅ "XXX（某人），您觉得怎么样？"
- ✅ 避免某个人垄断讨论

### 处理常见情况

**情况 1**：某人过度关注细节
```
主持人: "很好的细节！让我们先记下来，稍后再讨论。"
[贴粉色便签标记问题]
```

**情况 2**：两个人意见不一致
```
主持人: "很好的两个观点。我们都记下来，稍后和更多的人讨论。"
[贴粉色便签标记分歧]
```

**情况 3**：参与者不太活跃
```
主持人: "[名字]，从[角色]的角度看，会发生什么？"
```

## 工作坊后的行动

✅ **第 1 天内**：
- 整理便签内容
- 生成清晰的事件流图
- 列出问题清单

✅ **第 2-3 天内**：
- 与参与者分享整理结果
- 收集反馈和补充
- 修正遗漏的部分

✅ **第 1 周内**：
- 转化为详细的领域模型
- 开始流程模型分析
- 跟进标记的问题

## 常见问题 (FAQ)

**Q**: 如果某个事件很复杂，需要拆分吗？
**A**: 通常不需要。事件应该是原子的。如果太复杂，可能需要更细粒度的建模。

**Q**: 外部系统需要列得很详细吗？
**A**: 先识别出来即可。详细的集成设计可以后续深入。

**Q**: 如果流程中有太多的条件分支怎么办？
**A**: 这说明流程可能需要优化或拆分为更小的子流程。标记出来，后续用流程建模分析。

**Q**: Event Storming 需要全公司参与吗？
**A**: 不需要。聚焦在特定的业务范围（如订单处理）。不同的范围可以多次进行。
