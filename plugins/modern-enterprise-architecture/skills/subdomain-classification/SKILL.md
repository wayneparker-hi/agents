# Subdomain Classification

不是所有的业务域都同样重要。通过对业务域的分类（**核心域**、**支撑域**、**通用域**），帮助您做出正确的架构投资和资源分配决策。

## When to Use This Skill

- 🎯 **战略规划**：识别最有价值的业务域，集中投资
- 🏗️ **架构决策**：不同的域需要不同的架构方式
- 👥 **人员分配**：核心域应该由最好的团队负责
- 💰 **成本优化**：在通用域上降低成本，在核心域上提高质量
- 🔄 **演进规划**：不同类型的域的演进策略不同

## Core Concepts

### 1. 核心域（Core Domain）
**定义**：直接构成企业竞争优势、产生业务价值的业务域。

**特征**：
- 与企业的战略直接相关
- 是"做得最好的事情"，竞争对手难以复制
- 需要不断创新和改进
- 投资回报率高

**例子**：
- 对于电商平台：**推荐引擎**（如何让用户发现想要的商品）
- 对于支付宝：**风控系统**（如何识别欺诈）
- 对于滴滴：**匹配算法**（如何高效地匹配司机和乘客）

**架构建议**：
- 自主开发，不要依赖第三方
- 投入最好的工程师
- 频繁演进和优化
- 可以更复杂，只要带来价值

### 2. 支撑域（Supporting Subdomain）
**定义**：虽然不是核心竞争力，但是支撑核心域运作的业务域。

**特征**：
- 是"必须要做的事情"
- 但不是与众不同的
- 需要有，但不需要特别优秀
- 投资要找到平衡

**例子**：
- 对于电商：**物流配送**（虽然重要，但可以与物流公司合作）
- 对于支付宝：**商户管理**（必须有，但可以标准化）
- 对于滴滴：**客服系统**（必要但不差异化）

**架构建议**：
- 可以考虑采用现成的解决方案
- 投入中等的工程师
- 追求稳定和效率
- 标准化和可配置化

### 3. 通用域（Generic Subdomain）
**定义**：业界通用的、没有特殊要求的业务域。解决方案在所有企业都差不多。

**特征**：
- 是"每个人都要做的事情"
- 解决方案标准化
- 不构成竞争优势
- 应该最小化投资

**例子**：
- **用户身份认证**（所有系统都需要）
- **库存管理**（通用的库存逻辑）
- **账单系统**（计费逻辑大多相似）
- **邮件服务**（发邮件的逻辑都一样）

**架构建议**：
- 优先采用现成的第三方方案或开源库
- 只投入最少的工程师进行集成
- 争取快速实现，不过度工程化
- 标准化和自动化

## Classification Framework

| 维度 | 核心域 | 支撑域 | 通用域 |
|------|-------|-------|--------|
| **战略意义** | 高 | 中 | 低 |
| **竞争优势** | 直接 | 间接 | 无 |
| **复杂度** | 高 | 中 | 低 |
| **团队水平** | 最好 | 中等 | 可外包 |
| **实现方式** | 自主开发 | 自主或合作 | 第三方/开源 |
| **演进速度** | 快速 | 中等 | 缓慢 |
| **成本** | 高投资 | 中等投资 | 最低投资 |

## Step-by-Step Guide

### Step 1: 列出所有业务域
从能力模型或组织结构出发，列出所有主要的业务域。

**模板**：
```
1. 推荐引擎 - 基于算法给用户推荐商品
2. 用户身份认证 - 用户登录和权限管理
3. 商品搜索 - 用户搜索和发现商品
4. 订单处理 - 订单的创建、支付、发货
5. 库存管理 - 商品库存的管理和扣减
6. 物流配送 - 订单的发货和物流跟踪
7. 财务结算 - 平台和商家的账款结算
8. 营销活动 - 促销、优惠券等营销功能
```

### Step 2: 定义评估标准
对每个域进行多维度评估。

**关键维度**：

#### 战略意义
- ⭐⭐⭐⭐⭐ (5) - 直接关系到企业的核心战略
- ⭐⭐⭐⭐ (4) - 支持核心战略
- ⭐⭐⭐ (3) - 有一定的战略意义
- ⭐⭐ (2) - 战略意义有限
- ⭐ (1) - 几乎没有战略意义

#### 竞争优势
- ⭐⭐⭐⭐⭐ - 我们做得远好于竞争对手
- ⭐⭐⭐⭐ - 我们做得比较好
- ⭐⭐⭐ - 与竞争对手差不多
- ⭐⭐ - 竞争对手做得更好
- ⭐ - 竞争对手远好于我们

#### 复杂度
- ⭐⭐⭐⭐⭐ - 极其复杂，需要创新
- ⭐⭐⭐⭐ - 很复杂
- ⭐⭐⭐ - 中等复杂度
- ⭐⭐ - 相对简单
- ⭐ - 很简单

### Step 3: 评估每个域
对每个业务域进行评分。

**评估模板**：
```
域：推荐引擎
- 战略意义: 5 (直接决定用户的购买转化率)
- 竞争优势: 5 (我们的推荐准确度业界领先)
- 复杂度: 5 (需要复杂的机器学习和实时计算)
→ 分类: 核心域 ✓

域: 用户身份认证
- 战略意义: 2 (必要但不差异化)
- 竞争优势: 2 (与竞争对手差不多)
- 复杂度: 2 (标准的认证流程)
→ 分类: 通用域 ✓

域: 物流配送
- 战略意义: 3 (重要但非核心)
- 竞争优势: 3 (与竞争对手差不多，取决于物流网络)
- 复杂度: 3 (需要与物流公司集成)
→ 分类: 支撑域 ✓
```

### Step 4: 确定分类
根据评分结果，确定每个域的分类。

**判断规则**：
- **核心域**：战略意义高（≥4）且竞争优势强（≥4）
- **支撑域**：战略意义中等（2-3）或竞争优势中等（2-3）
- **通用域**：战略意义低（≤2）且竞争优势弱（≤2）

### Step 5: 制定差异化战略
根据分类制定不同的架构和投资策略。

**核心域战略**：
```
推荐引擎
✅ 自主开发，聚集最好的工程师
✅ 频繁迭代和优化（月度发布）
✅ 支持复杂的业务需求
✅ 投资模型训练和算法改进
✅ 与业务团队紧密协作
```

**支撑域战略**：
```
物流配送
✅ 自主开发核心逻辑，但与物流公司集成
✅ 投入中等工程师，关注可靠性
✅ 定期迭代，但不过度工程化
✅ 标准化流程，自动化关键环节
✅ 明确的 SLA 和监控
```

**通用域战略**：
```
用户身份认证
✅ 优先考虑第三方方案（如 Auth0）
✅ 只做最少的定制化开发
✅ 快速实现，最小化成本
✅ 重点是与其他系统的集成
✅ 尽量标准化，减少维护负担
```

### Step 6: 监测和调整
定期评审域的分类，反映业务的变化。

**评审频率**：
- 年度评审（随着战略调整）
- 季度评审（随着市场变化）
- 临时评审（当发现新机会时）

## Best Practices

1. **定期评审**：企业发展过程中，域的分类会变化
2. **团队对齐**：核心域应该吸引最优秀的人才
3. **避免过度工程化**：不要在通用域上过度投资
4. **支撑域的合作**：对支撑域，考虑与第三方合作
5. **明确的界限**：清晰地定义域的边界，避免重叠

## Common Pitfalls

- **❌ 所有域都当核心域**：导致资源分散，无法突出重点
  → **✅ 解决**：客观地评估，承认有些域就是支撑性的

- **❌ 忽视通用域**：认为"简单的不用管"
  → **✅ 解决**：虽然简单，但也要保证稳定和效率

- **❌ 分类不更新**：企业发展中，核心域可能变化
  → **✅ 解决**：定期评审和调整

- **❌ 与团队能力不匹配**：核心域由不够优秀的团队负责
  → **✅ 解决**：根据分类分配合适的人员

## Key Questions

- 我们真正与竞争对手不同的地方是什么？
- 如果我们在某个域失败，会有多大的影响？
- 这个域是我们必须自己做，还是可以与他人合作？
- 竞争对手在这个域的投资水平如何？
- 这个域的技术趋势如何？
