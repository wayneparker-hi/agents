# 核心域 vs 支持域

## 概念区分

### 定义

**核心域（Core Domain）**：
- 企业的主要竞争力所在
- 对业务成功至关重要
- 需要内部深度投资
- 例：电商的订单处理、推荐算法

**支持域（Supporting Subdomain）**：
- 支持核心域的运作
- 重要但非差异化
- 可以部分外包或使用成熟的第三方解决方案
- 例：电商的用户认证、订单通知

**通用域（Generic Subdomain）**：
- 完全通用，无差异化
- 可以购买或开源使用
- 例：电商的支付网关、短信服务

---

## 区分维度

### 维度 1：差异化程度

```
核心域：
  - 高差异化
  - 我们独有的做法
  - 竞争对手难以复制
  - 例：阿里的高并发处理、推荐算法

支持域：
  - 中等差异化
  - 有我们的特色，但不是主要区别
  - 例：订单通知流程、数据分析

通用域：
  - 无差异化
  - 所有人都一样
  - 例：支付、短信、邮件
```

### 维度 2：战略重要性

```
重要性排序：
  核心域 > 支持域 > 通用域

核心域：
  - 战略优先级：最高
  - 投资规模：大
  - 团队质量：最优秀的人

支持域：
  - 战略优先级：中等
  - 投资规模：中等
  - 团队质量：中等

通用域：
  - 战略优先级：最低
  - 投资规模：最小
  - 团队质量：不要求特别优秀
```

### 维度 3：发展成熟度

```
成熟度关系：
  通用域最成熟（已标准化）
  → 支持域相对成熟（有最佳实践）
  → 核心域仍在演进（持续创新）

结果：
  - 通用域：稳定、低成本
  - 支持域：相对稳定、中等成本
  - 核心域：变化快、高成本
```

## 识别核心域的方法

### 方法 1：价值链分析

```
价值链：原材料 → 生产 → 销售 → 服务 → 支付 → 报告

电商中：
  供应商 → 商品管理 → 订单创建 → 发货 → 支付 → 数据分析
              ↑         ↑                  ↑
           核心       核心                核心
  （我们的竞争力在这里集中）
```

### 方法 2：业务差异化

```
问题：我们和竞争对手的主要区别是什么？

电商答案：
  ✅ 核心域：
     - 我们的商品分类更全面
     - 我们的推荐算法更好
     - 我们的库存周转更快
     - 我们的价格更优竞争

  ❌ 支持域：
     - 物流用的都是一样的快递
     - 用户认证都是一样的

  ❌ 通用域：
     - 支付网关都是第三方
     - 短信都是用短信平台
```

### 方法 3：战略计划

```
问题：3-5 年的战略目标是什么？

电商答案：
  - 要成为行业第一：核心是商品和定价 → 核心域
  - 要成为用户体验最好：核心是推荐 → 核心域
  - 要成为全国覆盖：核心是物流协调 → 支持域
  - 要成为最便宜：核心是库存管理 → 核心域
```

### 方法 4：收益分析

```
问题：哪些域的改进能带来最大收益？

计算方式：
  收益 = (改进的效果) × (实现的概率) × (紧急程度)

电商示例：
  推荐算法改进 5% → 转化率 ↑ 10% → 收益 ★★★★★ → 核心
  物流速度 ↓ 1 天 → 满意度 ↑ 5% → 收益 ★★★★ → 支持
  支付时间 ↓ 1s → 交易成功率 ↑ 1% → 收益 ★★ → 通用
```

## 资源分配策略

### 投资分配

```
总投资 100%：

核心域：40-60%
  - 最优秀的团队
  - 最高的薪水
  - 最新的技术
  - 持续的创新

支持域：25-40%
  - 中等的团队
  - 标准的薪水
  - 成熟的技术
  - 定期的优化

通用域：10-20%
  - 维护团队
  - 基础薪水
  - 标准的技术
  - 按需维护
```

### 人员配置

```
核心域：
  - 需要领域专家
  - 需要架构师
  - 需要资深开发
  - 人员流失影响大 → 需要高薪留住

支持域：
  - 需要有经验的开发
  - 可以培养初级开发
  - 人员流动可以接受

通用域：
  - 可以用外包或众包
  - 可以只有一个维护人员
  - 可以完全用开源替代
```

## 常见误判

### 误判 1：把支持域当核心域

```
❌ 错误：
  把用户认证当成核心域
  投入大量资源自己实现

为什么错：
  - 用户认证是通用的，没有差异化
  - 业界已有成熟解决方案
  - 自己实现容易出安全问题

✅ 正确：
  - 购买或开源 OAuth 实现
  - 只维护必要的接口
  - 人员转向真正的核心域
```

### 误判 2：把通用域当支持域

```
❌ 错误：
  把短信通知作为支持域，自己实现短信网关

为什么错：
  - 短信网关是通用的
  - 比自己实现便宜 100 倍
  - 第三方有更好的可靠性

✅ 正确：
  - 用第三方短信服务
  - 只做集成
  - 人员和成本用在更重要的地方
```

### 误判 3：把核心域当支持域

```
❌ 错误：
  把推荐算法当支持域
  用标准的协同过滤，不做优化

为什么错：
  - 这是你的竞争力所在
  - 改进 1% 就能带来巨大收益
  - 竞争对手会超越你

✅ 正确：
  - 投入资源做推荐优化
  - 配备最好的 AI 团队
  - 定期创新和迭代
```

## 周期性重新评估

### 问题：分类会随时间改变吗？

```
答：会的！

原因 1：战略改变
  - 我们的战略优先级改变
  - 某个域从支持升为核心
  - 例：疫情前物流可能是支持，疫情后升为核心

原因 2：技术成熟
  - 曾经的核心域变得通用
  - 例：支付网关曾经是自己实现（核心），现在都是第三方（通用）

原因 3：市场变化
  - 新的竞争对手出现
  - 行业标准改变
  - 例：社交功能从通用变为核心
```

### 重新评估频率

```
建议：
  - 每年至少评估一次
  - 战略调整时立即评估
  - 市场变化时及时评估
```

---

## 关键建议

1. **不要贪心**：把所有东西都做成核心域是浪费
2. **专注投资**：把 50% 的资源投在 20% 的核心域上
3. **借力第三方**：通用域和大部分支持域用现成的
4. **定期评估**：至少每年重新评估一次
5. **清晰沟通**：让整个公司都理解分类和投资策略
6. **灵活调整**：战略改变时及时调整分类
