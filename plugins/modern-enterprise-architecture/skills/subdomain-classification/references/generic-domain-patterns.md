# 通用域模式与实现

## 通用域的特征

通用域是完全标准化、无竞争力差异的业务领域。它们有以下特点：

```
标准化程度：100%（所有公司都一样）
差异化价值：无
核心竞争力：无
战略重要性：低
投资优先级：最低
```

---

## 常见的通用域模式

### 模式 1：支付与结算（Payment & Settlement）

**特征**：
```
- 完全标准化的流程
- 法律和监管要求相同
- 每个电商都需要，实现都一样
```

**实现方式**：

```
❌ 自己实现（不建议）
  ├─ 成本：1000万+ RMB
  ├─ 时间：1+ 年
  ├─ 安全风险：高（涉及资金）
  ├─ 合规风险：高（需要金融牌照）
  └─ 收益：无差异化价值

✅ 第三方接入（推荐）
  ├─ 成本：< 100万 RMB
  ├─ 时间：2-3 个月
  ├─ 安全：第三方负责（PCI-DSS 认证）
  ├─ 合规：第三方处理
  └─ 收益：高

  常见的：支付宝、微信支付、银联等
```

**集成示例**：
```java
public class PaymentService {
    private final AlipayClient alipayClient;

    public PaymentResult processPayment(Order order) {
        // 只做集成，业务逻辑
        return alipayClient.pay(
            order.getOrderId(),
            order.getAmount()
        );
    }
}
```

### 模式 2：用户认证与授权（Authentication & Authorization）

**特征**：
```
- 标准的 OAuth2、SAML、LDAP
- 安全需求相同（密码加密、会话管理等）
- 大多数公司都用现成的解决方案
```

**实现方式**：

```
❌ 自己实现（不建议）
  ├─ 成本：300-500万 RMB
  ├─ 时间：半年+
  ├─ 安全风险：极高（涉及用户隐私）
  ├─ 维护成本：高（需要持续更新安全补丁）
  └─ 收益：无

✅ 开源 + 部署（可选）
  ├─ 成本：50-100万 RMB
  ├─ 时间：2-3 个月
  ├─ 安全：有社区维护
  ├─ 维护：定期更新补丁
  └─ 收益：有自主权，但维护成本高

  常见的：Keycloak、Auth0、Okta

✅ 云服务（最推荐）
  ├─ 成本：< 50万 RMB
  ├─ 时间：1-2 个月
  ├─ 安全：云服务商负责
  ├─ 维护：无
  └─ 收益：最高性价比

  常见的：AWS Cognito、Azure AD、Okta
```

**集成示例**：
```java
// 使用 Spring Security + Keycloak
@Configuration
public class SecurityConfig {
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) {
        http
            .oauth2Login()
            .and()
            .logout().logoutUrl("/logout");
        return http.build();
    }
}
```

### 模式 3：通知与通信（Notification & Communication）

**特征**：
```
- 邮件、短信、推送都是标准化的
- 规模化集中在少数大平台
- 自己实现成本很高，收益很低
```

**实现方式**：

```
❌ 自己实现邮件服务器
  ├─ 成本：50-100万 RMB
  ├─ 时间：2-3 个月
  ├─ 维护：高（需要处理退信、垃圾邮件过滤等）
  ├─ 可靠性：低（邮件服务器配置复杂）
  └─ 收益：无差异化价值

✅ 邮件平台（推荐）
  ├─ 成本：< 10万 RMB
  ├─ 时间：1 周内
  ├─ 维护：无
  ├─ 可靠性：高（专业平台处理）
  └─ 收益：高成本效益

  常见的：SendGrid、AWS SES、Mailgun、163、QQ 企业邮箱

✅ 短信平台（推荐）
  ├─ 成本：< 20万 RMB
  ├─ 时间：1 周内
  ├─ 维护：无
  ├─ 可靠性：高
  └─ 收益：高

  常见的：阿里云、腾讯云、融云、环信

✅ 推送平台（推荐）
  ├─ 成本：< 30万 RMB（小规模免费）
  ├─ 时间：1 周内
  ├─ 维护：无
  ├─ 可靠性：高
  └─ 收益：高

  常见的：友盟+、极光推送、小米推送
```

**集成示例**：
```java
public class NotificationService {
    private final EmailProvider emailProvider;
    private final SmsProvider smsProvider;

    public void notifyOrderCreated(Order order) {
        // 只做业务逻辑，具体实现委托给第三方
        emailProvider.send(
            order.getCustomer().getEmail(),
            "订单已创建",
            generateOrderSummary(order)
        );

        smsProvider.send(
            order.getCustomer().getPhone(),
            "您的订单已创建，订单号：" + order.getId()
        );
    }
}
```

**特征**：
```
- 日志管理是标准化的
- 监控告警的逻辑相同
- 行业已有成熟的平台级解决方案
```

**实现方式**：

```
  ├─ 成本：50-100万 RMB（部署和维护）

  ├─ 扩展性：好
  └─ 收益：中等

  工具：Elasticsearch、Logstash、Kibana

✅ 云日志平台（最推荐）
  ├─ 成本：< 50万 RMB
  ├─ 时间：1 周
  ├─ 可靠性：高（云服务商维护）
  ├─ 扩展性：自动
  └─ 收益：高成本效益

  常见的：阿里云日志、AWS CloudWatch、Google Cloud Logging
```

```
- 自己实现成本极高，收益为零
```

**实现方式**：

```

  ├─ 时间：1+ 年
  ├─ 可靠性：不确定
  ├─ 扩展性：有限
  └─ 收益：无差异化价值

✅ 云存储（推荐）
  ├─ 成本：按使用付费，< 100万 RMB/年
  ├─ 时间：1 周
  ├─ 可靠性：极高（99.99% SLA）
  ├─ 扩展性：自动无限扩展
  └─ 收益：极高

  常见的：阿里云 OSS、AWS S3、Google Cloud Storage
```

## 通用域的识别方法

### 问题 1：有现成的、成熟的、便宜的解决方案吗？

```
是 → 这可能是通用域

例子：
  支付 → 有支付宝、微信支付 → 通用域 ✅
  用户认证 → 有 Auth0、Okta → 通用域 ✅
  邮件 → 有 SendGrid、Mailgun → 通用域 ✅
  短信 → 有阿里、腾讯 → 通用域 ✅
  推荐算法 → 没有现成的 → 核心域 ❌
```

### 问题 2：这个功能实现的成本和收益比是多少？

```
收益/成本 < 0.1 → 通用域（不值得自己实现）
收益/成本 0.1-1 → 支持域（可以自己实现，也可以用第三方）
收益/成本 > 1 → 核心域（必须自己实现和优化）

例子：
  支付：成本 1000万，收益 0 → 比例 0 → 通用域 ✅
  推荐：成本 500万，收益 10亿（转化率↑10%） → 比例 20 → 核心域 ❌
  订单通知：成本 100万，收益 500万 → 比例 5 → 支持域
```

### 问题 3：我们的差异化在哪里？

```
如果差异化不在这个域 → 这可能是通用域

例子：
  电商的差异化：商品、定价、推荐、用户体验
  不是：支付、邮件、短信、文件存储
  → 后者都是通用域 ✅
```

## 常见的错误决策

### 错误 1：为了"自主权"自己实现通用域

```
❌ 错误想法：
  "我们不想依赖第三方，要自己实现支付"

为什么错：
  - 支付涉及资金，需要金融牌照
  - 需要 PCI-DSS 认证（成本巨大）
  - 持续更新安全补丁（维护成本高）
  - 完全没有差异化价值

✅ 正确做法：
  - 接入第三方支付
  - 在上层做自己的特色（优惠规则、支付路由等）
  - 这样既有自主权，又不浪费资源
```

### 错误 2：用全功能平台解决通用需求

```
❌ 错误想法：
  "我们的日志很重要，买一个全功能的 SaaS"
  每个月花 50k RMB

为什么错：
  - 日志本质上是通用的，不需要高级功能
  - 可以用便宜的方案（< 5k RMB）
  - 浪费钱在不会带来差异化的地方

✅ 正确做法：
  - 用最便宜的云日志服务
  - 够用就好，不要过度购买
  - 把省下的钱投在核心域
```

## 通用域管理清单

```
□ 是否已识别出所有通用域？
□ 是否为每个通用域选择了第三方方案？
□ 是否建立了集成层（避免直接依赖）？
□ 是否有备选方案（如果第三方故障）？
□ 是否定期评估成本效益？
□ 是否监控第三方服务的质量？
□ 是否有清晰的 SLA？
□ 是否做了容错和降级方案？
□ 是否有迁移计划（如果需要切换）？
□ 是否将省下的资源投入核心域？
```

---

## 关键建议

1. **优先使用第三方**：通用域的第一选择是用成熟的第三方
2. **建立抽象层**：不要让业务代码直接依赖第三方
3. **定期评估**：监控第三方的成本和质量
4. **准备备选**：有备选方案，以防需要切换
5. **成本控制**：不要过度购买，够用就好
6. **资源重点**：将省下的资源投入到核心域
